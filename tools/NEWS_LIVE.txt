Godel browser bridge

The open anonymous terminal's native POST /api/news/items returns HTTP200.
A single standalone HTTP compatibility check returned403: direct API access is
held. Do not replay this request, imitate browser headers, or use another client
to get around that refusal. The implementation has no Godel HTTP client.

Instead, the bridge passively copies successful responses the terminal fetches
itself. It sends no Godel requests, reads no cookies/passwords and never triggers
refresh, navigation or pagination. Keep the terminal open with the intended CEF
filter. The actual symbols, source selections, language and time range are saved.
An all-news or another stock's filter is not CEF coverage. A paginated historical
query is rejected. Native refusal stops capture for review.

The approved unpacked extension directory is:
  C:\Project\sec-research\tools\godel_bridge
Chrome: chrome://extensions -> Developer mode -> Load unpacked -> that directory.
It requests access only to app.godelterminal.com and localhost:8766, plus the
ability to inject the capture on the selected tab and retain session settings.
No new capture session starts automatically on browser startup. A user-started
daily Godel session can resume its existing lease after ordinary page navigation
within the terminal; leaving the supported terminal ends capture.

The popup shows saved updates, headlines in the last response, the last response's
actual filter, last receipt and time remaining. Multiple terminal panels can have
different filters. The label describes only the last captured response. The token
stays in extension session storage, is never sent to Godel, and expires with the local receiver. The receiver
binds only127.0.0.1, requires that token, limits bodies/rates/timeouts and disallows
arbitrary website origins. It makes no network requests. In Godel0.5.0 daily mode,
temporary loopback transport/5xx failures pause capture, then the minute alarm
resumes the same lease with a fresh capture ID after a healthy local status.
An ordinary terminal reload also resumes within that lease, without another code
or an extra source request. Short sessions still require explicit Resume.
Stop targets the paired tab even if another tab is active, and requests shutdown
of that session's local receiver. The popup distinguishes confirmed receiver
shutdown from an unconfirmed stop. Closing the paired tab, leaving the terminal,
terminal local HTTP/schema errors, or a native refusal stops capture. Source
refusals and copy failures are also retained locally when delivery to the receiver
fails. No failed capture POST is replayed. A new session never clears a hold.
Only the user starts a browser session. Automation may inspect its saved data,
but must not open/reload the terminal, change filters or start capture itself.
Keep Chrome, the paired terminal tab and the computer awake during a daily
session. Sleep, a lost receiver or a stale native feed is a recorded gap.
Ordinary Chrome service-worker suspension preserves the daily pairing; a full
browser restart or extension reload clears session storage and requires pairing
again. There is no automatic next-day or overnight authorization.

Selected Godel transport diagnostics (no tokens, account data or article bodies)
are bounded to128 entries in chrome.storage.local, with up to6 pending records
copied on an authenticated local status check to bridge_diagnostics in the
comparison SQLite store. They record status codes, worker revival and recovery
gap durations. A pending ring can truncate during a long outage; the local ring
and gap counters must be considered when reviewing incomplete diagnostics.

Interpretation and evidence

live.sqlite retains immutable raw-response files and hashes, original local IDs,
first observations, each subsequent copy, status/errors and durable holds. Items
with exact original BW/GNW/PRN URLs retain that wire identity. Missing original
URLs are explicit; local Godel IDs and provider names do not establish identity.
No credentials are stored in response archives.

Godel publicationTime (milliseconds), its vendor receivedTime, browser request
observation, browser body-copy completion and local receiver receipt are separate.
The passive copy is not claimed to be an exact network-completion event. The
browser clock must be within two minutes of the receiver; this bounds gross clock
errors, not precise synchronization. Physical screen delivery stays unmeasured.

Daily and session baselines, filter changes, long gaps, historical/unknown dates,
duplicate records and updated local IDs have separate classifications. A preceding
finite query result is a sampled response, not proof of global absence. New speed
comparisons still require reviewed original identity/title and primary fund body
evidence; newly_observed alone is not a validated release or latency guarantee.
