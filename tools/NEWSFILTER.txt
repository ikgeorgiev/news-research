The receiver prints an eight-character code valid for ten minutes. On the
signed-in Newsfilter search/latest-news tab, use Chrome's puzzle-piece Extensions
menu to open CEF Newsfilter news bridge, enter that code and click Connect &
start. The code goes in the extension popup, not Newsfilter's search box.
After pairing, a daily session keeps its midnight deadline even when that code
expires. Browse/search the paired tab normally; no automatic source refresh is
added. Do not restart a healthy receiver or start a duplicate for a fresh code.

The receiver is bound to 127.0.0.1:8767. There is no remote listener or cloud
deployment. Short-lived pairing, origin checks, 1-MiB limits, 20 events/minute
and bounded socket reads reuse the tested comparison receiver. Only one
receiver can bind that port. Keep the same store to preserve refusal controls.
Stop shuts down that receiver. Closing the paired tab or leaving the news
pages also stops the session. The short mode expires within 20 minutes; daily
mode expires at the same weekday's 22:00 UTC cutoff. An unpaired receiver closes
after its ten-minute pairing window; a daily receiver closes after five minutes
without its authenticated extension heartbeat/capture. Nothing starts on browser
or application startup. Keep Chrome, the paired tab and the computer awake.
Outside the authorized window, a deliberate implementation check requires
--compatibility-check; every resulting item is compatibility_history.

The extension observes only native POST https://api.newsfilter.io/actions
requests with type filterArticles, from=0 and size 1–100. It copies only news
ID, title, publication label, source name/ID, ticker tags and article links.
It sends NO Newsfilter requests, reloads, searches or pagination. Login and
account actions, cookies, Authorization headers and private fields are ignored.
Native refusals/errors stop capture. The receiver holds the source after a
refusal or schema failure, including 429 (no automatic retry; retain Retry-After).
Version 0.2.2 reads only response headers Chrome exposes to the page. Hidden
Date, Age and Retry-After headers stay absent; they are never probed, bypassed
or inferred. An exposed Retry-After is retained, and 429 still stops capture
and holds the source even when that header is unavailable. This removes the
"Refused to get unsafe header" console errors without changing page requests.
After updating, reload this extension in chrome://extensions, then reload the
Newsfilter page before starting a new bounded session. Historical Chrome error
entries may remain in its Errors view; compare timestamps and the new version.

Newsfilter searches perform a full navigation. Version 0.2 installs a dormant
request observer at document_start, before the site's page scripts. The
background must confirm an existing unexpired session for that exact tab and
document before any response body is copied. Other tabs remain inactive.
Request starts may be noticed during that short handshake; requests before
the user's original Start are excluded. Unpaired preparation expires after
15 seconds. No source request is initiated, delayed, blocked or replayed.
Each new document gets a fresh capture ID/baseline without extending the
original deadline. Version 0.2.1 also handles an XHR response that completes
while the extension background is busy: at most 20 references to the page's
existing completed requests wait for the lease. No body is read before that
lease; Stop, preparation expiry and reuse of the XHR discard stale references.
The native XHR completion timestamp stays separate from the later body-copy
and local-receiver timestamps. Fetch responses consumed by the page before
activation can still be unobserved; they are not an empty success or a speed
sample. Previous saved-update counts stay visible while a new page waits.
Continuous native auto-updates were not established by the weekend check.
Version 0.3.0 checks only the local receiver once per minute; it sends no source
request. LIVE means a recent native response was copied, while GAP / No recent
updates means there has been no native copy for three minutes. A daily lease
cannot make a static search page update. Automation may read saved copies but
must not start a receiver/browser capture or change the site's filters.
Version 0.3.1 also displays navigation/attachment stop reasons and sends a small
allowlisted stop reason to the local receiver. A final supported page URL alone
does not reconstruct a previously unrecorded navigation or explain a stop.

The selected search expression is retained up to 8192 characters, enough for the
prepared 367-symbol CEF query. Native acceptance remains a separate requirement.
Only narrowly recognized query templates receive an eligible-symbol count;
unknown filters remain unverified. Eligibility is not validated release coverage.
The source still returns at most 100 rows. Full pages, overlap, new documents
and native gaps are recorded; a gap or full-page turnover resets the baseline.
